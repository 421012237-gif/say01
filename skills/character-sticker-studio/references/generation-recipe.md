# 内置原版样片的绘图流程

客户只需本人照片和这次要做的表情；不向客户索取画风图或要求其描述画风。以下由Agent执行，不作为客户填写的表单。

## 从交付包取图

1. 读取assets/style/style-lock.json。能执行Node时运行scripts/resolve-style.cjs，检查两张生成样片和总览的真实位置与摘要。这个命令不绘图、不收费、不联网。
2. 打开返回的两张generationReferences。使用原24款你好源图约束整套画法，使用已确认的蕾丝样张保留细密发丝、自然五官和面部／材质笔触；总览仅作整套复核。
3. 将两张包内样片作为实际绘图输入，客户照片另作身份输入。首次默认顺序：原24款样片、细节样片、客户照片。没有客户照片时，若客户明确要虚构角色才按其文字设定生成；不凭空替代真人身份。
4. 无Node但可直接读取附件的宿主可按记录中的相对文件打开图片；必须确认是包内对应资产，不要求客户另外寻找风格参考。缺失或无法传入绘图工具则明确停止绘制准备，不使用纯文字冒充固定画风。

## 实际绘图指令骨架

“图1与图2为本Skill内置、已确认的同一画风样片。图1规定原24款表情的整体画法；图2补充自然五官尺度、细密发丝、面部微小笔触和复杂衣料细节。两图只决定怎么画，不能复制其中人物的面孔、鼻痣、发型、服装、首饰、性别或姿势。

图3是这次客户的唯一身份与穿搭依据，保留[从本次照片实际辨认出的五官关系、发型、服装和每件配饰]。按客户要求表现[表情、动作、景别]。保持内置样片的自然半身比例、轻微漫画整理、细弱内部面部线条、柔和但不磨平的肤色、细密且疏密有致的发丝、精细绘制的衣料和薄白边。不要将所有人统一为尖下巴、大眼睛、灿烂广告笑或光滑头像。主体轮廓之外为真实透明，不带辉光或背景块。

[逐项写清本次配饰所属人物／身体部位、位置、朝向、可见或被遮的部分]。缺少依据的细节不猜测，必要时先补问。不要移植参考人物的绿衣、吊坠、红珠串、戒指或头纱。输出[当前所需的一张小样或动作帧]。”

骨架中的方括号必须按本次照片替换。若生成工具的图片顺序不同，同步改指令，不能引用错图。样片中没有的动作细节不代表客户不存在；依据仍是客户原照和明确说明。

对照片中易漂移的长度和位置，记录相对身体标志：例如发梢落在肩部、锁骨或胸前的哪里，项链最低点相对领口的位置，头纱与眼睛／肩部的遮挡范围。不要只写“中长发”“有项链”等类别；复核也回到这些位置，避免细节画得精美却换了长度或款式。

动作包含掌心到手背转向时，先明确每帧真实的手掌骨架、拇指所在侧及前臂转动，再描述配饰的可见部分；不能复制同一手轮廓后只替换掌纹、指甲和戒面。戒指始终绑定人物的具体手指，按拇指邻接关系定位，不能按画面中的第几个竖条定位。局部返修既要说明该帧改变的朝向，也要锁定仍属于同一只手的腕饰和戒指位置。

## 成果与返修

直接对照包内原图检查具体画法；“同属漫画”“都有白边”不算通过。首次小样的画风、身份细节、空间逻辑分别记录。新动作使用已确认的本人物母版，并继续以包内原版样片核对，禁止依次用衍生图替换画风源。

返修只改明确偏差，保留身份与正确配饰；需要时继续附两张内置样片。记录真实生成次数、失败点、修正和结果。修了几次才达到要求就如实写几次，不宣称一次成功。

## 售前验收边界

包内有图、取图成功与生成画风通过是不同证据。首次验证需在新解压目录只用包内样片与客户照片绘图，记录人物类型、输出与失败；这仍不等于独立买家、新账号或多宿主验收。不同宿主若无法读取内置图、不能参考图绘制或无法交付文件，不列为已支持制作环境。当前Skill不控制底层模型权重或seed，不能承诺任意模型零偏差。
