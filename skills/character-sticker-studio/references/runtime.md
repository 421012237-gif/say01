# 运行环境与多端接续

## 开始前核对实际能力

一次任务只记录当前执行环境。宿主支持技能格式，不等于当前账号具备所有工具。读取已有有效记录，环境变化时再检查，不每次重做同样确认。

| 能力 | 有效依据 | 缺失时的处理 |
| --- | --- | --- |
| 读取人物参考并看图 | 当前可用的图像查看工具，已实际打开指定参考 | 请求可读取的必要参考；不编造脸部特征 |
| 参考图生成与编辑 | 当前工具清单与使用规则；能提供参考而非仅文生图 | 可处理既有帧；新人物生成仍待补齐工具 |
| 写入项目文件 | 当前授权工作区可保存文件 | 输出必要的交接文本；不能声称已保存文件 |
| 执行导出工具 | Node、sharp 与实际GIF编码检查 | 转到有执行器的工作入口或授权电脑，保留未完成状态 |
| 检查导出结果 | 能看源帧、输出帧及循环／播放器 | 格式通过后仍保持视觉待检查 |
| 交付文件 | 用户可下载真实GIF、PNG和ZIP | 给出实际成果位置及获取方法，不编造链接 |

可将结论保存到项目内的运行记录，写宿主、版本（可取得时）、手机／电脑入口、实际执行地点、工具名称、证据与缺失能力。不要在记录里写密钥或账号凭证。模型输出“我可以”不是工具证据。

实际循环检查可使用当前允许的本地GIF播放器，例如系统文件预览，不必依赖网页。用真实文件观察不同动作阶段与循环返回，再结合解码帧和延迟核对；仅显示第一帧、成功打开文件或单张截图不足以证明动画已播放。记录播放器、文件摘要和实际观察，不把用户尚未查看的预览链接当验收证据。某个网页被工具拒绝时，停止该页面操作；只有与被拒动作无关且本身获准的本地制作／文件预览才继续，不能借换入口访问同一被拒资源。

## 执行路径

1. 能看参考、能参考编辑、能写文件、能运行本地脚本：执行完整制作流程。
2. 有绘图但无脚本执行：先完成母版与源帧，保存接续说明；动态输出尚未完成。优先使用该产品本身的工作模式／云端执行器／已授权远程电脑。
3. 只有既有源帧和执行器：完成编码、格式检查和视觉复核；不声称新生成了图像。
4. 只有普通聊天：提供角色规范、动作提示和检查步骤，说明这是辅助流程。若用户要求完整GIF，明确缺少什么；不能静默交付成静态图片。

无原生透明背景能力时，先检查宿主是否有获准的图像编辑／抠图工具；不得把白底、棋盘格或黑底直接当成alpha。转用其他绘图服务会改变资料处理方和费用，遵循既有授权，不自动上传私人参考。

## 桌面、云端与手机

手机可发起工作任务，不代表脚本在手机本地执行。必须弄清本次执行器所在地及项目文件是否可访问：

- 云端任务有文件与运行时：在云端项目安装本包依赖并导出，通过该任务的附件功能交付。
- 远程电脑任务：用户已授权并连接的电脑负责运行；手机用于提出需求、确认和下载。电脑需按宿主要求保持可用。
- 手机无可用执行器：采用下一节接续模板，记录已完成和仍缺少的环节。

禁止把手机不能访问的桌面绝对路径当成下载链接。跨端看不到自定义技能时，先按当前宿主的安装／同步入口处理，不假称必然自动同步，也不要求买家公开付费Skill换取安装。

## 最小接续内容

使用 [接续模板](../assets/session-handoff.md)。转交角色规范、已确认母版、必要源帧、project.json和当前检查记录；已有导出须保留版本及摘要。只携带任务所需文件，不带无关照片库。源文件采用项目相对路径，不能嵌入上一台电脑的私人路径。

不要为了换工具重新设计人物。缺失源图或检查证据时继续保持待完成状态，不能从文字交接推断该帧已经通过视觉验收。
